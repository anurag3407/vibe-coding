# MODULE 3: ELITE PROMPT ENGINEERING & ITERATIVE DEBUGGING
### (Slides 46 to 70 | 20 Minutes)
*Goal: Teach non-technical attendees how to prompt like senior software architects. Avoid hallucinations, master chain-of-thought, negative constraints, and the art of error-message pasting.*

#### Slide 46: Title Slide - Module 3: Prompt Engineering for Builders
- **Headline**: The Art of Directing Intelligence
- **Visual**: Comparison of a lazy 5-word prompt vs an enterprise-grade structured prompt.
- **Key Takeaway**: The quality of your software is an exact mirror of the clarity of your instructions.

#### Slide 47: Why "Casual Chatting" Fails in Coding
- **Headline**: The Chatbot Trap
- **Example of Bad Prompt**: *"Make me an Uber clone for dog walking."*
  - **Result**: 50 lines of placeholder code, missing imports, fake API calls, broken logic.
- **Why it failed**: Underspecified requirements, zero technical boundaries, infinite degrees of freedom for the model to guess wrongly.

#### Slide 48: The R-G-C-C-O Framework for Elite Prompts
- **Visual**: 5-step interlocking block graphic:
  - **R**ole: Who is the AI acting as? ("Senior React & Tailwind Architect")
  - **G**oal: What exact feature or output are we creating?
  - **C**ontext: What tech stack, dependencies, and existing files exist?
  - **C**onstraints: What must it NOT do? (No external libraries, responsive mobile first)
  - **O**utput Format: Code only? Complete file replacement? Step-by-step diff?

#### Slide 49: Real Prompt Transformation (Before vs After)
- **Before**: *"Add authentication to my app."*
- **After**:
  ```markdown
  You are an expert Next.js 15 and Supabase developer.
  Goal: Implement email/password and Google OAuth authentication.
  Context: App is using Next.js App Router, Tailwind CSS, TypeScript, and @supabase/ssr.
  Constraints:
  - Do NOT use deprecated @supabase/auth-helpers-nextjs.
  - Implement protected middleware for /dashboard routes.
  - Provide complete code for app/login/page.tsx with clean error banners.
  Output: Step-by-step files with import paths.
  ```

#### Slide 50: Zero-Shot vs Few-Shot Prompting in Code
- **Visual**: Demonstration of Zero-Shot vs Few-Shot:
  - **Zero-Shot**: Asking for code without examples (Model uses general web training).
  - **Few-Shot**: Giving 1-2 examples of your coding style, component patterns, or API response format before asking for the new code.
  - **Why Few-Shot wins**: Code consistency increases by 80%!

#### Slide 51: Chain of Thought (CoT): "Think First, Code Second"
- **Headline**: Forcing the AI to Plan
- **The Magic Trigger Phrase**: *"Before writing any code, analyze the requirements, list potential edge cases, outline the data flow, and wait for my confirmation."*
- **Benefit**: Stops the LLM from hallucinating variables or painting itself into a corner mid-file.

#### Slide 52: Negative Prompting: Protecting Existing Architecture
- **Headline**: The "Do No Harm" Directive
- **Essential Negative Clauses to Add to Prompts**:
  - *"Do NOT rewrite unrelated functions or remove existing comments."*
  - *"Do NOT introduce new npm packages without explicit permission."*
  - *"Do NOT leave `// TODO: Implement later` placeholders—write full, working code."*
  - *"Preserve existing CSS class naming conventions."*

#### Slide 53: Modular Chunking: The 1-Feature-at-a-Time Rule
- **Visual**: Visual representation of building a car:
  - Wrong: Asking AI to build the engine, wheels, seats, and GPS in one giant prompt.
  - Right: Prompt 1: Engine block -> Verify -> Prompt 2: Transmission -> Verify -> Prompt 3: Wheels.
- **Rule of Thumb**: Never ask an agent to touch more than 2-3 files in a single prompt.

#### Slide 54: The Art of Pasting Errors Like a Pro
- **Headline**: Never Say: "It didn't work. Fix it."
- **The Perfect Bug Report Template**:
  ```markdown
  I ran this command: `npm run dev`
  Expected behavior: The login modal opens on click.
  Actual behavior: Blank white screen.
  Terminal error / Browser Console logs:
  [Paste exact error stack trace here]
  Relevant file: src/components/LoginModal.tsx
  ```

#### Slide 72: How LLM Context Windows Really Work
- **Visual**: The Context Bucket diagram:
  - Input: Tokens (System prompt + History + Project Files + Your Prompt).
  - Attention mechanism: LLMs pay the most attention to the beginning and very end of the context ("Lost in the Middle" problem).
  - Output: The next predicted tokens.
- **Takeaway**: If you stuff 100,000 tokens of junk into the context, the model gets "dumber" and hallucinates.

#### Slide 73: What is Context Engineering?
- **Definition**: The deliberate curation, structuring, pruning, and injection of relevant project information into the AI's active memory.
- **The Golden Equation**:
  $$\text{Elite Output} = \text{Precise Intent} + \text{Minimal Necessary Context} + \text{Strict Architecture Rules}$$

  - **Transport**: How they talk (Standard I/O `stdio` or Server-Sent Events `SSE`).

- **Visual**: Circular feedback loop:
  - Agent writes code ->
  - Agent automatically runs `npm run test` in background ->
  - Test fails with Error Code 401 ->
  - Agent reads error stack trace ->
  - Agent refactors code ->
  - Re-runs test -> Test passes (Green checkmark) ->
  - Reports "Task complete" to user!

#### Slide 225: Test-Driven Development (TDD) with AI
- **Headline**: The Secret to 100% Reliable Vibe Coding
- **The TDD Workflow**:
  1. Ask AI to write unit/integration tests for the feature *first* (e.g. using Vitest or Jest).
  2. Run tests -> They fail (Red).
  3. Tell AI: *"Generate the code to make all tests pass without modifying the test suite."*
  4. Watch them turn Green.

  - `/grill-me` : The agent interviews you to refine edge cases before coding.
